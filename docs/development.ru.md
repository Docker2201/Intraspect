# Сборка и выпуск версии

[← На главную](../README.ru.md)

Для обычного запуска используйте [готовый релиз](https://github.com/Docker2201/Intraspect/releases/latest). Эта страница нужна только при изменении кода.

## Собрать из исходников

На Windows запустите **`build.bat`** из корня репозитория. Скрипт найдёт подходящий JDK или скачает его вместе с JavaFX и библиотеками редактора. Все загрузки сохраняются в `launch/cache`; последующие сборки используют этот кэш. Не удаляйте его между сборками.

В чистом репозитории результат появляется в `launch/Intraspect`. Если уже есть рабочая папка `launch/Intraspect_Extended_3.96`, сборка обновит её на месте, сохранив `data`. Запуск — **`run.bat`**. Свой путь можно передать явно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File launch/build.ps1 -OutputDirectory launch/Intraspect
```

## Проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File launch/test-geometry.ps1
```

С установленным OCCT добавьте `-WithOcct`. Проверяются разбор NC, компенсация, переносимое хранилище, оба установа, геометрия инструментов и MCP.

В готовом ZIP нативный 3D-модуль уже есть. Для его изменения из исходников нужны Visual Studio с C++, CMake и OCCT; сборка — `launch/build-occt-bridge.ps1`. Для изменения Java-кода достаточно обычной сборки: без нативного модуля доступен встроенный построитель поверхности.

## Выпустить готовый ZIP

Не добавляйте JDK, DLL, папки сборки и личную `data` в Git. Соберите приложение, затем запустите упаковщик (Python 3, без сторонних пакетов):

```powershell
python tools/package_release.py --app launch/Intraspect --out out/release
```

Для существующей рабочей установки укажите её папку в `--app`. Упаковщик берёт только программу, встроенную Java, нужные DLL, примеры и документацию. Личная `data`, журналы, история и ключи MCP не включаются. Он создаёт `Intraspect-Windows-x64.zip` и `SHA256SUMS.txt`.

Проверьте распакованный ZIP из новой папки, затем прикрепите оба файла к GitHub Release с тегом версии. Имя ZIP сохраняйте: на него ведёт постоянная кнопка скачивания в README. Пользователь обновляет один архив, а не отдельные зависимости.

Исходники приложения — `src/main`; проверки — `src/test`; генератор инструментов — `assets/blender`; нативный мост — `native/occt-bridge`. В публичные примеры добавляйте только учебный NC, без производственных программ и чертежей.
